④ 为什么这样写（"报告-冒泡"模型）

每个 dfs 返回的语义
“我这棵子树里有谁”：只可能是四种答案——null（没货）、p（只有 p）、q（只有 q）、LCA（p 和 q 都在下面，答案已找到）。整个算法就是把这句话从叶子一路冒泡到根。
base case 三合一
root == null → 报告 null（这条路没货）。root == p/q → 报告自己，不再往下找——因为另一个目标要么在自己子树里（祖先情形），要么根本不在这条路，两种情况都无需继续，都由上层用"另一边是否为 null"自动分辨。
分叉点 = 答案（整棵树恰好出现一次）
当且仅当左、右报告都非空，p 和 q 分居两侧，当前节点就是最近公共祖先。之后它作为一个整体继续往上冒，上层只会看到一边非空，不会再产生第二个分叉点。
p 是 q 的祖先时为什么也成立
第一次遇到 p 就直接返回 p（根本不去找 q，q 就藏在 p 的子树里）。一路往上冒：p 所在链上，另一边永远是 null，于是 p 被原样递到根。如果 q 不在 p 子树里呢？那 q 一定在"另一边"的某条链上，分叉点会出现在 p 和 q 真正分开的那个祖先——算法不关心谁是谁的祖先，统一处理。
