class Solution {
public String decodeString(String s) {
Deque<Integer> numStack = new ArrayDeque<>();
Deque<String> strStack = new ArrayDeque<>();
String cur = "";
int num = 0;
for(int i = 0; i < s.length(); i++){
char ch = s.charAt(i);
if(ch >= '0' && ch <= '9'){ // ① 数字：累加倍数
num = num * 10 + (ch - '0');
}else if(ch == '['){ // ② 进内层：存现场
numStack.push(num);
strStack.push(cur);
num = 0;
cur = "";
}else if(ch >= 'a' && ch <= 'z'){ // ③ 小写字母：当前层拼
cur += ch;
}else{ // ④ 兜底 = ']'：取现场
int k = numStack.pop();
String temp = "";
for(int j = 0; j < k; j++){
temp += cur;
}
String pre = strStack.pop(); // 弹在 temp 之后，两个栈互不干扰
cur = pre + temp; // 前缀接回，同层继续拼
}
}
return cur;
}
}

双栈版在做什么：手工递归

  1. cur = 我现在这一层正在拼的串；num = 我正在读的那个倍数。
  2. 遇到 '[' 就压两下：把「本层倍数」交给 numStack，把「本层已拼好的部分」交给 strStack，然后 num、cur 归零，开始拼里层。这正是递归调用前保存局部变量。
  3. 遇到 ']' 走 else，分三步结算：先弹 numStack 拿倍数 k → 用里层的 cur 抄 k 份造出 temp → 再弹 strStack 拿前缀 pre → cur = pre + temp。等价于把递归返回值交回调用方。
  4. 两栈必须成对压弹，深度才不错位；栈深 = 括号嵌套深度。
  5. 判据顺序是 数字 → '[' → 小写字母 → else：']' 是唯一三条都不成立、落到兜底的字符，所以 else 里不用再写 ch == ']'。

四路分支对照表

① ch>='0' && ch<='9' → num = num*10 + (ch-'0')
为什么：ASCII 数字是连续编码，比区间就够判，还比 Character.isDigit 更严（后者连全角 '２' 都算数字）。倍数可能连着好几位，要边读边左移；拼好先攥在 num 里，等 '[' 来认领它是哪层的倍数。
写错：num = ch-'0' → 12[a] 解成 aa（只剩最后一位）。
② ch == '[' → 两个 push，再 num=0、cur=""
为什么：要跳进内层，本层的「倍数 + 已拼到一半的前缀」必须整套存下来 —— 这就是递归调用前的现场保存。
写错：漏 cur="" → 里层把外层已拼的 "a" 当自己的起点，3[a2[c]] 解成 aacacaacacaacac。
③ ch>='a' && ch<='z' → cur += ch
为什么：字母既不切层也不带倍数，纯粹属于当前层的内容，接到 cur 尾巴上就行；外层前缀此刻锁在 strStack 里，不会互相污染。题目保证只有小写，所以区间判断安全。
写错：把这条判据漏掉 → 字母落到 else 被当 ']' 弹栈，3[a] 第一个字符 'a' 就 pop 空栈，抛 NoSuchElementException。
④ else（兜底 = ']'）→ 弹 numStack 得 k → temp 抄 k 份 → 弹 strStack 得 pre → cur = pre + temp
为什么：']' 是唯一走到兜底的字符，用 else 省掉一次比较。栈顶恰好是最近一次 '[' 存的那层现场（LIFO 对齐当前括号）；temp 保证是"抄 k 份"，而不是"自己翻倍自己"。两个栈各弹各的，k 先弹、pre 后弹不影响配对。
写错：漏 pre + → 2[abc]3[cd]ef 丢掉 abcabc，只剩 cdcdcd 拼 ef；写 cur += cur → 长度指数爆炸。

五个易错点

  • cur = temp（漏了 pre）→ 2[abc]3[cd]ef 会丢掉 abcabc 这段同层前缀。
  • 忘写 num = 0 → 3[a2[b]] 的外层 3 会一直留着，里层被读成 32[b]。
  • 多位数只能用 num*10 + (ch-'0')，直接把字符接成字符串会漏掉 12、100 这类倍数。
  • 用 else 兜底 ']' 有代价NoSuchElementException。反过来把 else 当字母，则是把垃圾静默拼进结果。两种写法都建立在"输入合法"这个前提上 —— 面试时值得主动说一句。
  • String 不可变，+= 每次都新建对象：解码后长度 L 时最坏 O(L²)。想省就用 StringBuilder，思路与栈结构完全不变。

看动画时盯什么

  • ④ 每步只有一条亮：紫底 ✓ 是这轮真正执行的分支；它上面那几条标 ✗ 不成立（判据真的被跑过），下面那几条标 — 短路（连判断都不发生）。']' 因为前三条全不成立，所以只有 ④ 亮。
  • ⑤ 用「旧值 → 新值」列出这一帧到底动了谁：⇑ push / ⇓ pop / cur += 'a' / cur = pre + temp，没动的变量不出现。
  • ⑦ 的三步流水线按你这版代码的顺序走：先弹 numStack 得 k → 造 temp → 最后才弹 strStack 得 pre。所以 ⑤ 里 strStack 的 ⇓ pop 是和 cur = pre + temp 同一步出现的。
  • ② 的弧从灰 → 紫（正在展开）→ 绿（已折回 cur），和 ⑥ 两个栈的压入弹出同步发生。
  • ③ 里 蓝色格子是弹回来的 pre、绿色格子是新拼上的 temp，能直接看出为什么是 pre + temp。
  • 栈里永远存着「上一层欠着的现场」，所以最外层那一条弧（root）要到最后一步才变绿。

复杂度

  • 时间：读串 O(n)，拼接产出 L 个字符；本实现用 +=，最坏 O(L²)。
  • 空间：栈深 = 最大嵌套深度 d，加 cur/temp 的输出缓冲 → O(n + L)。
同一套逻辑换 DFS 写法：递归函数返回当前层的串，遇到 '[' 就递归进去 —— 双栈只是把系统调用栈换成自己维护的两个 Deque。
